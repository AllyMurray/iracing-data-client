The client provides the core functionality for connecting to the iRacing Data API, handling OAuth2 authentication, and managing requests.

## IRacingDataClient

The main entry point for using the Data Client.

```typescript
import { IRacingDataClient } from 'iracing-data-client';

const iracing = new IRacingDataClient(options);
```

### Constructor Options

```typescript
interface IRacingClientOptions {
  auth: AuthConfig;
  fetchFn?: FetchLike;
  validateParams?: boolean;
  validateSemanticParams?: boolean;
  stores?: HttpClientStores;
  retry?: RetryOptions | false;
  rateLimit?: Omit<HttpClientRateLimitOptions, 'store'>;
  observability?: HttpClientObservabilityOptions;
}
```

<Tabs>
  <TabItem label="auth">
    **Type:** `AuthConfig` (required)

    Authentication configuration. A discriminated union of two OAuth2 flows:

    - `PasswordLimitedAuth` — for scripts, CLIs, and backend services
    - `AuthorizationCodeAuth` — for web apps acting on behalf of other users

    See [Authentication Configuration](#authentication-configuration) below for full details.

    ```typescript
    const iracing = new IRacingDataClient({
      auth: {
        type: 'password-limited',
        clientId: process.env.IRACING_CLIENT_ID!,
        clientSecret: process.env.IRACING_CLIENT_SECRET!,
        username: process.env.IRACING_USERNAME!,
        password: process.env.IRACING_PASSWORD!,
      },
    });
    ```
  </TabItem>
  <TabItem label="fetchFn">
    **Type:** `FetchLike` (optional)

    Custom fetch implementation for HTTP requests. Useful for testing or environments without global fetch.

    ```typescript
    const iracing = new IRacingDataClient({
      auth: { /* ... */ },
      fetchFn: myCustomFetch,
    });
    ```
  </TabItem>
  <TabItem label="validateParams">
    **Type:** `boolean` (optional, default: `true`)

    Enable or disable runtime parameter validation using Zod schemas.

    ```typescript
    const iracing = new IRacingDataClient({
      auth: { /* ... */ },
      validateParams: false,
    });
    ```
  </TabItem>
  <TabItem label="validateSemanticParams">
    **Type:** `boolean` (optional, default: `true`)

    Enable or disable semantic validation for known endpoint parameter combinations (e.g. validating that a `seasonId`/`carClassId` pair exists).

    ```typescript
    const iracing = new IRacingDataClient({
      auth: { /* ... */ },
      validateSemanticParams: false,
    });
    ```
  </TabItem>
  <TabItem label="stores">
    **Type:** `HttpClientStores` (optional)

    Pluggable stores for caching, deduplication, and rate limiting, powered by `@http-client-toolkit/core`. When omitted, the SDK operates without external stores.

    Available store keys:
    - **`cache`** — A `CacheStore` for caching S3 responses. TTL is automatically derived from presigned URL expiry.
    - **`rateLimit`** — A `RateLimitStore` or `AdaptiveRateLimitStore` for local request throttling.
    - **`dedupe`** — A `DedupeStore` for deduplicating concurrent identical requests.

    ```typescript
    const iracing = new IRacingDataClient({
      auth: { /* ... */ },
      stores: {
        cache: myCacheStore,
        rateLimit: myRateLimitStore,
        dedupe: myDedupeStore,
      },
    });
    ```

    See the [Caching Guide](/iracing-data-client/guides/caching/) and [Rate Limiting Guide](/iracing-data-client/guides/rate-limiting/) for detailed examples.
  </TabItem>
  <TabItem label="retry">
    **Type:** `RetryOptions | false` (optional, default: `false`)

    Enables built-in retry with exponential backoff for transient failures, including network errors, 429 responses, and 5xx responses. Retries are disabled by default.

    ```typescript
    import { DEFAULT_RETRY_OPTIONS, IRacingDataClient } from 'iracing-data-client';

    const iracing = new IRacingDataClient({
      auth: { /* ... */ },
      retry: DEFAULT_RETRY_OPTIONS,
    });
    ```
  </TabItem>
  <TabItem label="rateLimit">
    **Type:** `Omit<HttpClientRateLimitOptions, 'store'>` (optional)

    Configures rate-limit behavior for the underlying HTTP client. Pair this with `stores.rateLimit` when you want local throttling to wait instead of throw.

    ```typescript
    const iracing = new IRacingDataClient({
      auth: { /* ... */ },
      stores: {
        rateLimit: myRateLimitStore,
      },
      rateLimit: {
        throw: false,
        maxWaitTime: 60_000,
      },
    });
    ```
  </TabItem>
  <TabItem label="observability">
    **Type:** `HttpClientObservabilityOptions` (optional)

    Subscribe to structured lifecycle events from the underlying HTTP client, including request outcomes, cache behavior, dedupe joins, rate-limit waits, server cooldowns, and retry scheduling.

    ```typescript
    const iracing = new IRacingDataClient({
      auth: { /* ... */ },
      observability: {
        onEvent(event) {
          if (event.type === 'request:success') {
            console.log(event.url, event.durationMs);
          }
        },
      },
    });
    ```
  </TabItem>
</Tabs>

## Authentication Configuration

The `auth` option accepts a discriminated union (`AuthConfig`) of two OAuth2 flows.

### Password Limited Flow

For scripts, CLI tools, and backend services running on behalf of the registered client owner. This is the most common flow.

```typescript
interface PasswordLimitedAuth {
  type: 'password-limited';
  clientId: string;
  clientSecret: string;
  username: string;
  password: string;
  tokens?: {
    accessToken: string;
    refreshToken?: string;
    expiresAt?: number;
  };
  onTokenRefresh?: OnTokenRefresh;
}
```

The client authenticates automatically on the first API call. You can optionally provide pre-obtained `tokens` to skip the initial token request, and an `onTokenRefresh` callback to persist tokens for reuse across sessions.

```typescript
const iracing = new IRacingDataClient({
  auth: {
    type: 'password-limited',
    clientId: process.env.IRACING_CLIENT_ID!,
    clientSecret: process.env.IRACING_CLIENT_SECRET!,
    username: process.env.IRACING_USERNAME!,
    password: process.env.IRACING_PASSWORD!,
    onTokenRefresh: async (tokens) => {
      await fs.writeFile('tokens.json', JSON.stringify(tokens));
    },
  },
});
```

### Authorization Code Flow

For web and desktop applications that access data on behalf of other users. Requires completing the OAuth flow externally before creating the client.

```typescript
interface AuthorizationCodeAuth {
  type: 'authorization-code';
  clientId: string;
  clientSecret: string;
  tokens: {
    accessToken: string;
    refreshToken?: string;
    expiresAt?: number;
  };
  onTokenRefresh?: OnTokenRefresh;
}
```

Use the exported helper functions to complete the flow:

```typescript
import {
  IRacingDataClient,
  buildAuthorizationUrl,
  exchangeAuthorizationCode,
} from 'iracing-data-client';

// Step 1: Build the authorization URL and redirect the user
const { url, state, pkce } = await buildAuthorizationUrl({
  clientId: process.env.IRACING_CLIENT_ID!,
  redirectUri: 'https://myapp.com/callback',
  usePKCE: true,
});

// Step 2: Exchange the authorization code for tokens (in your callback handler)
const tokens = await exchangeAuthorizationCode({
  clientId: process.env.IRACING_CLIENT_ID!,
  clientSecret: process.env.IRACING_CLIENT_SECRET!,
  code: callbackCode,
  redirectUri: 'https://myapp.com/callback',
  codeVerifier: pkce?.verifier,
});

// Step 3: Create the client with the obtained tokens
const iracing = new IRacingDataClient({
  auth: {
    type: 'authorization-code',
    clientId: process.env.IRACING_CLIENT_ID!,
    clientSecret: process.env.IRACING_CLIENT_SECRET!,
    tokens: {
      accessToken: tokens.access_token,
      refreshToken: tokens.refresh_token,
    },
    onTokenRefresh: (newTokens) => {
      // Persist refreshed tokens for the user's session
    },
  },
});
```

## IRacingClient

The underlying client that handles HTTP requests. You typically don't interact with this directly.

### Features

<Card title="Automatic OAuth2 Authentication" icon="key">
  Handles the complete OAuth2 flow including token acquisition, Bearer header injection, and automatic token refresh.
</Card>

<Card title="S3 Link Following" icon="refresh">
  Automatically follows presigned S3 URLs returned by the API for accessing data.
</Card>

<Card title="Pluggable Stores" icon="suitcase">
  Supports optional caching, deduplication, and rate limiting via `@http-client-toolkit/core` stores.
</Card>

<Card title="Parameter Transformation" icon="arrow-left">
  Automatically converts between camelCase (SDK) and snake_case (API) formats.
</Card>

### Internal Methods

The client provides these internal methods (used by services):

#### `get<T>(url, options)`

Makes a GET request to the API.

```typescript
async get<T>(
  url: string,
  options?: {
    params?: Record<string, unknown>;
    schema?: ZodSchema;
  }
): Promise<T>
```

#### `isAuthenticated()`

Returns `true` if the client has valid, non-expired tokens.

```typescript
isAuthenticated(): boolean
```

#### `clearTokens()`

Clears stored tokens, requiring re-authentication on the next request.

```typescript
clearTokens(): void
```

## Error Classes

### IRacingError

Error thrown for iRacing Data API errors (non-2xx HTTP responses).

```typescript
class IRacingError extends Error {
  status?: number;           // HTTP status code
  statusText?: string;       // HTTP status text
  responseData?: unknown;    // Response body

  // Computed helper properties
  get isMaintenanceMode(): boolean;  // True if 503 maintenance
  get isRateLimited(): boolean;      // True if 429 rate limit
  get isUnauthorized(): boolean;     // True if 401 unauthorized
}
```

### OAuthError

Error thrown for OAuth-related failures (token requests, invalid credentials).

```typescript
class OAuthError extends Error {
  code: OAuthErrorCode | string;
  description?: string;
  uri?: string;

  get isInvalidGrant(): boolean;
  get isInvalidClient(): boolean;
  get isRateLimited(): boolean;
  get isUnauthorizedClient(): boolean;
}
```

### TokenRefreshError

Error thrown when token refresh fails and no recovery is possible. Extends `OAuthError`.

```typescript
class TokenRefreshError extends OAuthError {
  cause?: Error;
}
```

### Error Handling Examples

<Tabs>
  <TabItem label="Basic">
    ```typescript
    import { IRacingError } from 'iracing-data-client';

    try {
      const data = await iracing.member.info();
    } catch (error) {
      if (error instanceof IRacingError) {
        console.error(`API Error: ${error.message}`);
        console.error(`Status: ${error.status}`);
      }
    }
    ```
  </TabItem>
  <TabItem label="Specific Errors">
    ```typescript
    import { IRacingError, OAuthError, TokenRefreshError } from 'iracing-data-client';

    try {
      const data = await iracing.member.info();
    } catch (error) {
      if (error instanceof TokenRefreshError) {
        console.log('Session expired - user needs to re-authenticate');
      } else if (error instanceof OAuthError) {
        if (error.isInvalidClient) {
          console.log('Invalid client credentials');
        }
      } else if (error instanceof IRacingError) {
        if (error.isMaintenanceMode) {
          console.log('iRacing is in maintenance mode');
        } else if (error.isRateLimited) {
          console.log('Rate limited - wait before retry');
        } else if (error.isUnauthorized) {
          console.log('Authentication failed');
        }
      }
    }
    ```
  </TabItem>
  <TabItem label="With Retry">
    ```typescript
    import { IRacingError } from 'iracing-data-client';

    async function withRetry<T>(
      fn: () => Promise<T>,
      retries = 3
    ): Promise<T> {
      for (let i = 0; i < retries; i++) {
        try {
          return await fn();
        } catch (error) {
          if (error instanceof IRacingError) {
            // Don't retry auth errors
            if (error.isUnauthorized) throw error;

            // Retry rate limits with backoff
            if (error.isRateLimited && i < retries - 1) {
              await new Promise(r =>
                setTimeout(r, Math.pow(2, i) * 1000)
              );
              continue;
            }
          }
          throw error;
        }
      }
      throw new Error('Max retries exceeded');
    }

    // Usage
    const data = await withRetry(() =>
      iracing.member.info()
    );
    ```
  </TabItem>
</Tabs>

## Performance Considerations

### Caching

When a `CacheStore` is provided via the `stores` option, the client caches S3 responses with TTL derived from the presigned URL expiry:

- Cached responses are returned immediately without making a new request
- Cache TTL is automatically calculated from the S3 link's `expires` field
- Without a `stores.cache`, no caching is performed

See the [Caching Guide](/iracing-data-client/guides/caching/) for setup and store implementations.

### Rate Limiting

<Aside type="caution">
  The iRacing API has rate limits. The client will throw an `IRacingError` with `isRateLimited = true` when limits are exceeded.
</Aside>

Best practices:
- Provide a `RateLimitStore` via `stores.rateLimit` for local throttling
- Enable built-in retry with `retry` when you want automatic backoff for transient failures
- Batch requests where the API supports it

### Connection Pooling

The client reuses the same authenticated session across all requests:

```typescript
const iracing = new IRacingDataClient(options);

// All these requests share the same OAuth tokens
await iracing.member.info();
await iracing.car.get();
await iracing.track.assets();
```

### Pending Requests

Use `getPendingRequestCount()` to inspect in-flight request pressure. Pass a resource key to scope the count to a single rate-limit bucket.

```typescript
const totalPending = iracing.getPendingRequestCount();
const apiPending = iracing.getPendingRequestCount('https://members-ng.iracing.com');
```
