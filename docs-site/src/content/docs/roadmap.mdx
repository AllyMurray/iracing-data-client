This page outlines planned features and improvements for the iRacing Data Client.

## Upcoming Features

### Built-in Cache Store Utilities (High Priority)
**Status:** Planned

Convenience cache store implementations and observability on top of the existing `stores.cache` integration.

**Features:**
- Memory-efficient cache with configurable size limits
- Cache statistics and debugging tools
- Per-endpoint cache control

### Request Queue Helpers (Medium Priority)
**Status:** Planned

Convenience helpers for queueing and observing high-volume request workflows. Built-in retry with backoff is available through the `retry` client option, and local throttling is available through `stores.rateLimit`.

**Features:**
- Request queue with configurable concurrency
- Rate limit statistics

### Browser Support (Low Priority)
**Status:** Under consideration

Full browser compatibility with CORS handling.

**Features:**
- Browser-compatible authentication flow
- CORS proxy support
- Web Worker support for background operations

### CLI Tool (Low Priority)
**Status:** Planned for future release

Command-line interface for quick data access.

**Features:**
- Interactive authentication
- Data export to CSV/JSON
- Batch operations
- Shell completion

## Recently Completed

### v0.4.x
- Upgrade to `@http-client-toolkit/core` v4
- Opt-in automatic retry with exponential backoff for transient failures
- Configurable rate-limit wait behavior for pluggable rate limit stores

### v0.2.x
- Opt-in pluggable stores for caching, rate limiting, and request deduplication
- Automatic cache TTL derivation from iRacing presigned URL expiry when `stores.cache` is provided

### v0.1.0
- OAuth2 authentication (Password Limited and Authorization Code with PKCE)
- Automatic token refresh with configurable callbacks
- Full TypeScript support with generated types
- Automatic authentication and session management
- S3 link following for data retrieval
- Parameter transformation (camelCase to snake_case and back)
- Comprehensive error handling (maintenance mode, rate limit detection, auth errors)
- 15 service classes covering 72+ endpoints
- Runtime parameter validation with Zod schemas
